# 单独修复已批准的 GPU 环境

环境迁移失败后，项目页提供“仅修复 GPU 环境（不启动训练）”。该操作沿用已经单独批准的 TensorFlow GPU 迁移方案，复用项目现有 Conda 环境，不创建新环境，也不调用实验执行入口。

服务接口为 `POST /api/projects/{project_id}/reproductions/{run_id}/repair-environment`。只允许已批准迁移、已经失败或暂停、并且项目中没有其他活动任务的记录。原失败原因、依赖快照及各次安装日志保留。

迁移成功须同时通过依赖安装、`pip check` 和 GPU 实际矩阵运算验证。通过后将任务暂停，等待用户点击“继续未完成实验”。仅完成安装包下载、依赖预检或 GPU 枚举都不作为完整迁移成功。

修复过程中可以暂停。恢复未完成的环境修复时，仍保持只修复环境的意图，不转入训练。网络失败只作有限重试；依赖冲突、源码或环境归属变化仍需重新核验。

已校验主安装包及完整下载分段可复用。本机代理连接失败时，普通 pip 安装和本服务自带的校验安装器可对同一软件源进行当前子进程内的直连重试，不改变系统代理或 TLS 校验。原失败日志与最新结果分别保留，错误分类以最后一次结果为准。

每个 8 MB 下载分段允许最多 180 秒，并通过最低传输速度与停滞时限防止无限等待；安装操作本身仍受总体时限约束。所有官方 wheel 在发布缓存及安装前须通过注册信息和 SHA256 校验。
