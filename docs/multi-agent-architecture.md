# ReproMind 多 Agent 与 MoMA 对接设计

## 1. 比赛要求映射

| 比赛关注点 | ReproMind 实现 |
|---|---|
| Agent 设计与开发 | Research Orchestrator 加五个专业 Agent，使用 LangGraph 运行 |
| 多模型调度 | `ModelRouter` 根据 Agent 角色选择 router、chat、coder、reasoning 模型 |
| 智能路由 | Orchestrator 综合用户目标与证据类型选择四条工作流之一 |
| 上下文管理 | `ResearchState`、证据清单、内容限长、SHA-256 版本标识和 Checkpointer |
| 真实业务场景 | 医疗科研与工业研发中的论文复现、配置核验、实验结果可信审计 |
| MoMA 模型服务 | `MODEL_PROVIDER=moma` 后统一通过 MoMA OpenAI 兼容网关调用 |
| 安全与可靠性 | 实验命令经人工批准后在项目工作区与独立 Conda 环境中执行；环境归属、数据来源、执行路径和结论证据分别核验 |

## 3. 路由策略

| 路由 | 节点序列 | 适用请求 |
|---|---|---|
| `paper_review` | Orchestrator → Paper → Report | 只抽取论文证据 |
| `reproduction_plan` | Orchestrator → Paper → Code → Reproduction → Report | 生成复现方案 |
| `result_audit` | Orchestrator → Audit → Report | 已有结果的快速检查 |
| `full_audit` | Orchestrator → Paper → Code → Reproduction → Audit → Report | 四源联合可信审计 |

路由模型可用时由模型判断；模型未配置或返回非法结果时，使用可解释的确定性规则降级。

## 4. 多模型策略

Agent 不直接读取模型 ID。所有调用进入 `backend/app/core/model_router.py`：

```text
Agent role → logical model kind → provider model ID → OpenAI-compatible API
```

比赛部署设置 `MODEL_PROVIDER=moma`，分别配置：

- `MOMA_MODEL_ROUTER`：低成本、低延迟分类模型；
- `MOMA_MODEL_CHAT`：论文抽取与报告生成模型；
- `MOMA_MODEL_CODER`：代码理解与复现规划模型；
- `MOMA_MODEL_REASONING`：跨来源实验审计模型。

若专业模型失败，路由器可降级到通用模型；若所有模型不可用，确定性工具仍生成基础报告。

## 5. 上下文与证据

- ORM 文件实体在进入图前转换为可序列化证据对象；
- 单文件与总上下文分别限长，控制 Token 成本；
- 每份证据记录 SHA-256，防止报告与文件版本错配；
- `thread_id = project:{project_id}:run:{analysis_id}`，隔离不同项目和运行；
- Agent 只传递结构化 `paper_profile`、`code_profile`、计划和发现；
- 最终报告保存 Agent、模型、耗时、Token、降级和错误轨迹。

## 6. 与 EduAgent 的关系

项目借鉴其 Orchestrator、Agent 独立状态图、LLM Factory、结构化输出、上下文传递和失败降级思想。科研业务状态、Prompt、路由、工具、数据库模型、审计规则与前端均为重新实现，没有复制其教育业务代码。

## 7. 自主复现的可靠性边界

自主复现与只读论文审计分开。当前优先完成作者开源仓库与上传源码路线，未开源论文自动编码已暂缓。Source Agent 先识别论文中的仓库链接、获取作者代码或上传源码，再结合 README、入口文件与论文提取实验信息。不能因论文驱动编码的范围短引文不合格而阻止作者仓库获取，也不能因克隆失败生成替代代码。失败时允许重试、提供正确仓库或上传源码，保留旧草稿和历史记录。Data Agent 识别数据；Environment Agent 首次建立项目环境，后续核验并复用现有环境；Execution Agent 运行已批准命令并收集指标；Result Agent 按逐数据集证据核验结论。报告不能把流水线完成率等同论文复现率。

作者源码路线仍要求明确的数据集与指标。信息抽取失败时保留已获取源码、具体错误和重试操作，不能伪造论文数值，也不启动实验。普通 argparse 与旧 TensorFlow `flags.DEFINE_string/enum` 的数据集参数分别识别，为不同数据集规划独立命令，不能将所有记录都执行为默认数据集。环境安装和训练必须等待用户批准。

以下论文驱动编码和方法审查机制保留为历史组件及测试，不再由当前自主复现入口调用；其严格范围引文门槛不用于作者源码流程。

数据发现按以下顺序进行，并保存来源：

1. 作者仓库内的真实文件，包括嵌套 `data_set`、缩写目录、完整的 `ind.*` 文件组与代码中的相对路径。只看到目录、空文件或 Git LFS 指针不算可用。
2. README、其他文档及论文中的下载说明。直链在人工批准后下载，压缩包检查路径与解压规模，再按作者加载器所需目录安装；资料页仅保留为线索。
3. 作者关联仓库中的完整数据文件组。若获取失败，记录具体网络或格式错误。
4. Hugging Face 与 Zenodo 的公开候选。只有完整且与加载器兼容的文件组可自动下载；仅名称或标题相似不能证明它是论文版本，报告标记版本未核验。
5. 仍缺数据时说明缺失文件、已找到的资料页和搜索错误，允许重新检索、上传准确文件或明确选择部分实验。

环境构建在创建成功时写项目归属记录，在全部依赖和 GPU 检查通过后才写就绪标记。安装遇到明确的临时网络错误仅重试一次；包版本不兼容与超时分别记录，不用猜测性改装污染现有环境。

论文驱动编码由 `services/code_agent.py` 执行有界循环，而非一次 JSON 返回整个项目：先规划 2–5 个平面 Python 模块，再逐文件接收源码正文。每个文件至多尝试三次，输出截断至多续写两次；续写从完整行边界开始，避免直接拼接半个字符串。语法错误优先保留此前的顶层定义，只重写出错定义及其后的内容。检查不导入或执行生成模块；除编译与本地导入符号外，还通过 Python 符号表查未定义全局名称，并检查静态可确定的本地函数调用参数。闭包、局部同名变量、可变参数等不做猜测性阻断；动态命名空间明确标记部分覆盖。

方法审查至多三轮修复、四轮复核，确保最后一次修复后仍有复核机会。阻塞意见必须提供真实文件中的唯一短源码片段；方法偏差还须提供可回查完整论文的原文。审查意见逐项核验：有效意见立即进入修复台账，无效引文和未定位意见单独补证，不能因为一条无效意见丢弃整轮有效问题。纠正一次响应后仍有无效意见时，可以先修复已定位问题，再复核；只有问题台账和响应核验都完成才允许通过。保存原始审查意见、校验原因与补充证据，失败保留草稿，不冒充源码编译失败。当前目标明确要求而代码未实现的微调、训练、核心算法或划分不能作为黄色限制放行；外部检查点未提供不等于训练实现缺失。缺失可选扩展与已实现训练属于不同事实，否定词不能跨分句绑定。按有效样本数终止的循环、丢弃无效行等静态风险只是调查提示，不直接判为算法错误。

问题台账随编码计划保存，状态为待处理、已修改待复核、已复核解决。复核必须逐项回应上轮问题，遗漏不算解决；仍未解决而旧片段已变化时，必须重新定位当前源码。语义修复保护证据范围之外的既有函数、类及类方法；无源码语义变化时停止无效重试。错误响应或回归修复不得覆盖原有有效草稿。页面与 Copilot 区分模型请求、文件校验、方法审查和当前问题，不把历史审查意见累计为完整生成失败次数。模型辅助复核仍不等于执行测试或科学正确性证明。

论文上下文优先保留方法、实验、实现附录，并识别 PDF 分隔大写标题。论文规范必须包含非空明确的数据集、指标及有论文短引文支撑的复现范围（required/optional）；旧空规范或摘要级含糊规范不能因历史 enriched 标记继续编码。核心实验目标不默认包含所有消融、基线或扩展，用户目标明确选择扩展时应列为必需；目标变化需重新核验范围。规范提取最多两次，失败停在理解论文阶段，显示实际错误和重试操作，保留当前计划和源码草稿；重试不能跳过规范直接进入编码或旧批准训练。每次写入保存文件、阶段、错误和用量；重试复用同一任务范围内的有效文件，不自动覆盖其他实验的源码。Copilot 可以读取草稿原文，并区分“草稿存在”“编译通过”“模型辅助方法审查完成”和“真实实验验证完成”。模型审查通过不是科学正确性的证明，运行能力仍需后续环境与真实数据验证。

论文上下文为数值超参数、微调与数据划分预留预算，章节边界识别附录小节与参考文献，防止长方法章节挤掉实现设置。当前检查状态和此前诊断分开：最近五轮准备记录保存数据、环境、命令与审查快照；重新生成时清除当前的旧通过标记和限制说明。数据重试复用未变动且通过审查的生成源码，不重新请求编码；显式重新生成、未解决核心限制、源码变动或草稿未完成时重新审查。

数据公开性、来源身份、下载状态、加载格式与论文版本分别记录。官方适配目前覆盖 LITO 的六个表格数据集：Default、Shoppers、Obesity、Satimage 的 UCI 元数据，以及 Sick、Pima Diabetes 的 OpenML 固定 ID。简称歧义需要论文特征描述确认；未知数据集仍使用一般候选检索，不宣称已适配。仅生成实现使用统一 CSV/manifest 合同，作者代码不自动改用不兼容表格。批准执行后在当前项目解释器解析官方 CSV/ARFF，核对目标列、行数/特征数（元数据提供时）和校验和，记录原始哈希、列名、缺失值与移除的官方 ID 列；不自动补值、编码、删样本或重新划分。公开数据未核实论文处理版本时，实验结果仍标记版本待核；本地无清单或已变动的数据文件不得覆盖。

实验执行只允许项目工作区内的命令及模型环境；缺少输出目录、第三方依赖等可确定问题做有限修复，并保留修复记录。作者脚本若写死数据路径，只在独立源码副本中准备其他数据集的运行命令；未核对该数据集超参数时，实验结果保持“配置待核”，不打论文结论复现勾。不能安全生成独立命令的数据集明确列为未规划，不静默省略。首次项目环境创建、后续环境复用与检查、代码修改确认和实验运行确认分别处理。

离线回归：在 `backend` 目录执行 `python -m pytest tests -q`。Agent 图测试显式注入未配置密钥的模型路由，不读取开发者凭据调用外部模型。该测试集检验平台控制流程和确定性校验，不证明任意未开源论文都能自动复现；真实模型输出、环境、数据与科研结果仍须分阶段验证。

Windows 检查点存储与实验子进程使用不同事件循环：应用保留支持子进程的 Proactor，PostgreSQL/psycopg 检查点 I/O 调度到专用 Selector 工作线程。适配器覆盖异步读取、写入、pending writes、流式历史和线程删除，并传递异常与取消；停止服务时关闭连接池和线程。不再在应用导入阶段修改全局事件循环策略。持久化不可用时仍降级内存，但健康接口明确返回 `status=degraded`、`persistent=false` 与错误，而不是宣称完全正常。
