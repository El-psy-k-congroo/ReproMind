# ReproMind 多 Agent 协作设计

系统由复现引擎和项目编码服务管理任务状态，按阶段调用具有明确输入输出的 Agent 角色。各角色共享项目上下文，可以使用同一模型，也可以按能力组选择模型。

| 角色 | 输入 | 输出与协作 |
|---|---|---|
| Paper Agent | 论文正文、作者说明和项目材料 | 提取方法、数据集、参数和指标，交给准备与规划流程 |
| Code Planning Agent | 用户需求、所选运行、源码和设备环境 | 确定修改范围、关联文件与实现方案 |
| Code Agent | 规划结果、文件内容和校验反馈 | 生成代码候选和逐行差异，反馈校验问题后继续修改 |
| Semantic Review Agent | 需求、方案及代码差异 | 检查是否满足需求、是否改动正确文件与实验范围 |
| Repair Agent | 运行命令、异常日志、环境与源码 | 诊断运行问题，生成并验证修复，交回执行流程 |
| Project Copilot | 当前论文、源码、数据、运行与用户对话 | 回答项目问题，识别修改或运行意图，交给相应流程 |

```text
用户目标 / 复现助手
  → 复现引擎：论文理解 → 作者源码 → 环境与数据 → 执行计划
  → 用户确认 → 运行实验 → 指标与曲线 → 报告
                         ↓ 异常
                     Repair Agent → 校验与重试

修改需求 → Planning Agent → Code Agent → Semantic Review Agent
                                ↑              ↓
                                └── 校验反馈 ──┘
                         → 差异预览 → 确认应用 → 新实验
```

源码下载、环境安装、数据核对、命令执行、指标采集和绘图由工程工具与规则承担。界面的流程阶段与上述模型角色相互配合，不要求每个阶段各自运行一个独立模型进程。

## 模型与框架

统一模型路由按 router、chat、coder、reasoning 四个能力组选择服务。HTTPX 请求移动云 MoMA 或通用兼容对话接口；LangChain 的 `langchain-openai` SDK 列入依赖。`core/checkpoint.py` 保留 LangGraph 的 InMemorySaver 与 AsyncPostgresSaver 适配。当前主流程使用 Python 异步编排和业务数据库状态，没有通过 StateGraph 执行。

## 上下文与状态

论文、源码文件、运行命令、数据集、设备、环境和日志按项目与运行关联。编码流程读取具体文件及所选实验，生成差异预览；执行流程保存命令、日志与指标。任务状态写入 SQLAlchemy 业务实体，默认由 SQLite 持久化。外部实验使用项目独立 Conda 环境，在用户确认计划后启动。
